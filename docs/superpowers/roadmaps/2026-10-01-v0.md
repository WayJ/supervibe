# plugin v0.1.0 published

Epic E1 is supervibe's self-hosting epic: it dogfoods the plugin's own artifact
model to carry its own v0 implementation. The sprint below started before this
epic doc existed (the spec/plan pair predate the epic scaffold) — the stub row
records the as-found state, per the ledger rule that pre-start states live only
here and started states live in the sprint doc's frontmatter.

| deliverable | note |

## Decisions (ADR)

| id | decision | rationale | date | evidence |
|---|---|---|---|---|
| D1 | Skills-only plugin: five skills coupled by the artifact contract, no daemons/agents; superpowers stays the execution layer and is dispatched to, never forked | artifact-contract coupling keeps each skill small and testable; the five-skill set covers roadmap→start→accept→merge→sync with sync as the only cross-sprint writer | 2026-10-01 | spec §4 |
| D2 | Dated-directory artifact model (`docs/superpowers/{roadmaps,sprints,acceptances}/YYYY-MM-DD-<name>.md`) with a decentralized ledger — pre-start state in epic stub rows, active state in sprint frontmatter | learned from superpowers' own dated dirs and gstack's repo-local artifacts; a central index rots, directory scan cannot | 2026-10-01 | spec §2 (revision f3133be) |
| D3 | Read-only roadmap viewer = one self-contained static page (`web/board.html` + classic-script `web/parser.js`) shipped with the plugin; directory access via folder picker (webkitdirectory, Chromium handle persistence), zero network, zero build/generator; plans listed by link only, never parsed | a `file://` page cannot read paths by string (URL params included) — the pick gesture is the only portable grant; parser/aggregation stays in-browser so no index file ever lands on disk and the decentralized ledger is preserved; visual system per DESIGN.md warm-editorial tokens with local font fallbacks | 2026-10-01 | specs/2026-10-01-board-design.md |
| D4 | merge skill renamed `complete` (Jira "Complete Sprint" alignment); bare `merge` trigger word dropped | the trigger word collided with git-merge requests — every "merge this PR" risked firing a sprint close-out; the agile-standard action name removes the overlap (board likewise set `disable-model-invocation: true`) | 2026-10-31 | b8e19d4 |
| D5 | `merged-commit` anchored to the **main-side landing commit** (was: sprint branch tip) | squash/rebase hosts never make the branch tip an ancestor of main — clause arrival checks silently never fired; anchoring the landing point keeps the trigger semantics true under every merge style | 2026-10-31 | spec §2.2 |
| D6 | complete stage order: merge → ledger finalize → teardown (was: teardown before ledger), plus an interruption/resume protocol routing on existing artifacts | a crash between teardown and the ledger write left a landed sprint with neither record nor carrier and no in-skill resume path; record first, destroy second | 2026-10-31 | spec §4 |
| D7 | gate-evidence block + mechanical short-circuit: the acceptance record carries (branch tip hash, gates list as run, green outputs); complete re-runs gates verbatim only on any mismatch | accept and complete ran the same gate suite twice per close-out — the largest wall-clock tax; mechanical equivalence (tip + list unchanged) preserves the "green against today's tree" invariant without judgment | 2026-10-31 | spec §2.6 |
| D8 | sync event-driven (mandatory after every complete landing and on any detected external landing; calendar fence only when >1 sprint in flight) + durable report note `notes/YYYY-MM-DD-sync.md` (no-doc-creation invariant relaxed to exactly this note) | at WIP 1 cadence rounds were structural no-ops — main's only scheduled writer is complete itself; and the report lived only in the conversation, so the next session's accept/complete/sync could not read it | 2026-10-31 | spec §2.4/§2.5 |

| D9 | Add a thin read-only workflow validator: tree-bound acceptance, reacceptance revocation, active+acceptance WIP, and merged+closed dependency semantics | closes stale-pass and WIP gaps without a daemon or workflow engine; fingerprint excludes only the new record and three review metadata fields; supersedes D1's no-helper boundary | 2026-10-31 | spec §2.5.1; scripts/validate-workflow.mjs; retrospective for the initial documentation edits made before this ADR, subsequent implementation follows this decision |

| D10 | Simulation hardening: WIP sees all linked worktrees, scaffold preserves empty owned directories, and recovery recognizes an already-landed merge with its carrier still present | isolated branch ledgers, Git empty-directory omission, and no-ff interruption were found in the workflow simulation; no cross-clone lock or implicit push | 2026-10-31 | spec §2.5.1; start/roadmap/complete skills; simulation findings |

| D11 | Shared common-dir runtime ledger with mkdir lock, revision CAS and idempotent operation IDs; Markdown is a projection, not runtime authority | user requested authoritative cross-worktree state; reserve admission atomically, preserve interrupted reservations, explicit init/import, no branch-scan fallback; supersedes D2 runtime authority and D10 admission scanning | 2026-10-31 | docs/shared-ledger.md; spec §2.5.1; scripts/shared-ledger.mjs |

| D12 | SuperVibe iteration defaults to multi-agent; explicit solo routes to superpowers before any iteration side effects. Sprint evidence and final Roadmap integration acceptance are separate mandatory gates | one worker plus coordinator is still multi-agent; all sprint passes cannot prove integrated user outcomes; no substituted UI evidence or silent capability fallback | 2026-10-31 | spec §11; scripts/acceptance-contract.mjs; scripts/iteration-route.mjs |
